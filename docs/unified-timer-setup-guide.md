# Timer setup and running guide

## Start with a working timer

A new installation opens an unsaved working timer directly. Tap its name to edit it in place. Until you choose a custom name, the name follows the main interval. A single interval shares the configuration name and has no separate step-name field.

Use the familiar duration presets and sound row. The horizontal control row opens run length, clock alignment, the full volume mixer, cue vibration and alarm options. Their summaries show the configured values after you move to another control. Default vibration profiles, alarm defaults, schedules, appearance, Focus and system integrations are in the three-dot Settings menu.

## Add steps and sub-bells

**Add step** turns the main body into compact cards. Hold a card's dotted handle to drag it into a new position. The surrounding cards animate into place while dragging. Tap a card to edit its name, duration, sound, volume, vibration or end alarm in a sheet, using the same interval editor as the one-step page. Its editable name is the heading; duplicate/delete commands live in its three-dot menu. Run length and clock alignment apply to the whole ordered round.

The whole sub-bell summary card opens the sub-bell list; only its toggle changes enablement. Tap a bell to edit its name inline, sound and cadence. **Repeat** controls the fixed cadence without erasing selected offsets. Random gaps, after-start and before-end cues can be combined. The action row sits below the editable bell title. Random toggles on/off; color, offsets, vibration and watch-face visibility reveal focused controls. Bell volume stays visible. Duplicate/delete commands live in the three-dot menu. Shortening an interval retains dormant points. A fully selected repeating cadence follows cadence changes and adds the new occurrences when its interval grows; customized selections and dormant points remain intact.

Drag the handle to expand or reduce a sheet. Tap its backdrop or drag down from the partial view to dismiss the top layer. Android Back, Escape and accessibility handle actions provide alternatives. Sound choices open in a shorter sheet above the cue editor, with Back returning one layer. There are no generic Done, Expand or Collapse toolbar buttons. Web scrollbars are hidden without disabling scrolling, and Settings remembers its menu position when returning from a section. Selections are applied to the working draft as you edit; explicit save, import and confirmation actions remain where needed.

## Save and switch configurations

For a bounded run, **Add completion sound** appears beside **Add step**. Its cue and removal options stay here, separate from alarm defaults.

**Save** creates a saved configuration for an unsaved timer, or updates the currently selected saved configuration. Save is disabled when a saved configuration has no draft changes. Use the configuration icon beside Save (also available under **Settings → Configurations**) to switch, use **Save as…** for the current draft, rename, duplicate, delete, import/export or change running-selector visibility.

Configuration cards show each step’s duration and sub-bell timeline; rename, duplicate, export and delete are grouped in their three-dot menus.

Each saved configuration keeps a saved snapshot and a separate durable draft. Dirty switching offers Save, Keep draft, Discard or Cancel. Save as selects the new card and preserves the outgoing draft. Library actions do not discard another configuration's edits. The unsaved working timer is retained independently and can be reopened from the library.

## Running and recovery

Starting uses a frozen snapshot. Setup drafts and library actions do not replace the accepted run. Existing running watchface and immediate controls remain; previous/next skip steps silently and pause/resume retain timing and sound position.

Existing saved records remain intact. Legacy work copies, presets, settings and sounds retain their migration/recovery paths. A legacy flat timer with no library becomes a working copy rather than an invented saved card. Unreadable/future records are preserved for recovery. The retired experiment's key is not read or promoted.
